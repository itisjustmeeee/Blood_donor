# Blood donor console application

Рабочее консольное приложение находится в каталоге `bloodcenter`. Оно использует
пакетную структуру `ru.mirea.project`, PostgreSQL через JDBC и таблицы из
`sql_script/blood_donor.sql`.

## Подготовка базы данных

1. Создайте базу PostgreSQL `blood_donor`.
2. Выполните файл `sql_script/blood_donor.sql`.
3. Проверьте параметры подключения в
   `bloodcenter/src/main/java/ru/mirea/project/util/DatabaseManager.java`.

Подключение повторяет исходную конфигурацию:

```text
jdbc:postgresql://localhost:5432/blood_donor
user: postgres
```

## Запуск

Из каталога `bloodcenter`:

```powershell
mvn compile
mvn exec:java
```

При запуске приложение проверяет наличие базы `blood_donor` в PostgreSQL.
Если базы нет, она создаётся автоматически, после чего создаются типы и
таблицы приложения. Для этого пользователь PostgreSQL должен иметь право
`CREATEDB`. При повторном запуске существующая база и схема не создаются
заново.

Если в терминале IntelliJ IDEA русские символы отображаются как `����`,
проверьте настройку **Settings | Editor | General | Console | Default Encoding**:
должно быть выбрано `UTF-8`. Для встроенного терминала PowerShell в настройке
**Settings | Tools | Terminal | Shell path** укажите `powershell.exe`.

[Console]::InputEncoding = [System.Text.Encoding]::UTF8
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8

Приложение дополнительно принудительно использует UTF-8 для стандартного вывода
и ввода. После изменения кода выполните `mvn clean compile`, чтобы пересобрать
классы.

Консоль поддерживает регистрацию и вход, создание записей на донацию,
медицинские обследования, обработку результатов, просмотр групп крови,
партий и выполненных донаций. Донор и врач могут изменить дату записи на
медицинское обследование или удалить запись. Изменение даты синхронно обновляет
дату связанной заявки, а обследование, по которому уже оформлена донация,
удалить нельзя.

В главном меню есть пункт **«Внести тестовые данные»**. Он добавляет
идемпотентный набор: донора с семью обследованиями и несколькими донациями,
донора с обследованием без донации, донора с положительным обследованием и
донацией, донора с отклонённым обследованием, врача и всего десять записей на
медицинское обследование. Семь обследований принадлежат первому донору, три —
остальным донорам. Повторный выбор пункта не дублирует записи.

Для тестовых пользователей используется пароль `password`, а email-адреса
имеют домен `example.com`.

Проект разделён на слои:

- `ui` — консольный интерфейс и ввод/вывод;
- `service` — бизнес-правила и сценарии приложения;
- `repository` — JDBC-доступ к PostgreSQL;
- `model` — предметные модели;
- `exception` — бизнес- и доменные исключения;
- `util` — подключение к БД (`DatabaseManager`) и экспорт (`ExcelExporter`);
- `security` — хеширование паролей.

Телефон в профиле пользователя не хранится; для входа используется email.

Репозитории соответствуют таблицам
`blood_group`, `donor`, `donation_request`, `medical_examination`,
`blood_batch` и `donation`.

Пароли сохраняются в `donor.password_hash` как SHA-256-хеш длиной 64 символа.
Тестовые записи в SQL-файле используют пароль `password`; в реальном проекте
следует использовать более стойкий алгоритм с солью, например Argon2id или bcrypt.

При регистрации указывается возраст пользователя. В таблице `donor` используется
поле `age`, а регистрация пользователей младше 18 лет запрещена. При запуске
существующей базы приложение переносит значение из старого `birth_date` в
возраст и удаляет устаревшее поле.
